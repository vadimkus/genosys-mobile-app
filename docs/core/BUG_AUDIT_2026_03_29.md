## Detailed Fix Descriptions

### Phase 1: `utils/cartUtils.js` (2 issues)

**#15 — `Number()` coercion on `itemCount` (HIGH)**
`items.reduce((sum, item) => sum + item.quantity, 0)` could concatenate strings if `quantity` was stored as a string from AsyncStorage. Changed to `sum + (Number(item.quantity) || 0)`.

**#48 — Case-insensitive emirate lookup (LOW)**
`getShippingCost` compared emirate names with `===` (exact match). Now normalizes both sides with `.trim().toLowerCase()`, consistent with `calculateCartTotals`.

---

### Phase 2: `contexts/CartContext.js` (14 issues)

**#1-3 — Unified `hasServerDiscount` helper (HIGH)**
Three places (`loadCartFromStorage`, `addItem`, `updateSize`) each had subtly different logic to determine if a discount is server-confirmed. Extracted into a single `hasServerDiscount(variantOriginal, variantPrice, variants, product)` function that checks:
1. Variant has `originalPrice > price`
2. Any variant in the array has `originalPrice > price`
3. Product has a `discountLabel`

**#17 — Re-normalize cart on user change (MEDIUM)**
Added a `useEffect` that re-applies personalized pricing when `user?.id` or `locale` changes after initial load.

**#18 — `updateColor` variant pricing (MEDIUM)**
`updateColor` was only updating the color but not re-deriving the price from the variant. Now looks up the variant by size and applies the correct price + discount.

**#19 — Memoize context value (MEDIUM)**
Wrapped the provider's `value` object in `useMemo` to prevent all consumers from re-rendering on every state change.

**#20 — Memoize getter functions (MEDIUM)**
Wrapped `getTotalItems`, `isInCart`, `getItemQuantity`, `getCartTotals`, `getCartSummary`, `getAvailableEmirates` in `useCallback`.

**#39-41 — Dead code removal (LOW)**
Removed `promoTickRef`, `itemsRef`, and `shippingRates` from unnecessary dependency arrays.

---

### Phase 3: `contexts/FavoritesContext.js` (3 issues)

**#25 — Ref-based async state (MEDIUM)**
Replaced the fragile `Promise.resolve()` flag pattern in `addToFavorites`/`removeFromFavorites` with `favoritesRef.current` for synchronous current-state reads inside async callbacks.

**#26 — Stale `toggleFavorite` closure (MEDIUM)**
`toggleFavorite` checked `favorites.some(...)` which could be stale. Now reads from `favoritesRef.current`.

**#10 — Store full product data (HIGH)**
The `newFavorite` object now includes `displayPrice`, `originalPrice`, `category`, `discountLabel`, and `variants` — enabling the favorites grid to render discount badges and strikethrough prices correctly.

## Architecture Improvements

### Before → After

| Area | Before | After |
|------|--------|-------|
| Product grid | `ScrollView` + `.map()` (all items rendered) | `FlatList` + `numColumns={2}` (virtualized) |
| Discount logic | 3 divergent inline implementations | Single `hasServerDiscount()` helper |
| Badge logic | 40-line blocks duplicated in 2 files | Shared `utils/badges.js` module |
| Context value | New object every render | `useMemo`-wrapped, stable reference |
| Getter functions | New functions every render | `useCallback`-wrapped |
| Favorites data | `id/name/image/price` only | Full product object with discount/category/variants |
| Async state reads | `Promise.resolve()` flag pattern | `useRef` for synchronous reads |
| RTL support | Hardcoded `left/right/marginLeft/marginRight` | Logical `start/end/marginStart/marginEnd` |
| API badge data | `_badgeMap` side-property on array | Clean `{ categories, badgeMap: Map }` return |

### Security Improvements
- Order response logs no longer contain customer PII
- Profile picture uploads use authenticated requests
- URL path segments properly encoded (prevents injection)
- Legacy plaintext tokens cleaned up after SecureStore migration
- SecureStore failures properly caught (no silent fallthrough)

### Reliability Improvements
- Empty order submissions blocked at client level
- Order numbers have 8 extra bits of entropy
- Session validation always returns a defined shape
- `response.json()` / `.text()` calls wrapped in try/catch
- `Linking.openURL` rejections caught
- Cart totals recalculated on user/locale change

## Update System (Reference)

The app has a three-tier update mechanism:

| Tier | Component | Behavior |
|------|-----------|----------|
| **Force Update** | `ForceUpdateScreen.js` | Full-screen blocker when installed version < `minimumVersion` |
| **Soft Update** | `UpdateBanner.js` | Dismissible top banner when installed version < `latestVersion` |
| **OTA** | `config/updates.js` + `expo-updates` | Silent background download, applies on next restart |

Controlled by `GET /api/mobile/app-version?platform=ios|android` on the website (`cosmetics-website/app/api/mobile/app-version/route.ts`). Current config: `minimumVersion: "1.5.0"`, `latestVersion: "1.8.0"`.

## Post-Audit UI Fixes: Variant Chip Layout (Same Session)

After the 50-issue audit OTA, two additional commits refined the variant chip layout in the bag screen based on TestFlight QA.

### Problem

Variant selector chips (size and color) in the bag were wrapping onto too many rows:
- **Microneedle Roller** (5 sizes): displayed 2+2+1 rows — wanted 3+2
- **Revita Glow colors** (#01 Bright, #02 Natural): displayed on 2 rows — wanted 1 row
- **BB Cushion colors** (Beige, Ivory, Camel): displayed 2+1 — wanted 1 row

### Fix (2 commits)

**Commit `c215435`** — `ui: compact variant chips to fit more per row in bag`
| Property | Before | After |
|----------|--------|-------|
| `variantChip.paddingHorizontal` | 7px | 6px |
| `variantChip.paddingVertical` | 4px | 3px |
| `variantChipsRow.gap` | 4px | 3px |
| `variantChipText` font size | 12px (`T.captionSmall`) | 10px |
| `variantSelectorLabel` font size | 12px (`T.captionSmall`) | 10px |
| `variantSelectorLabel.marginBottom` | 3px | 2px |
| `variantSelectorWrap.marginBottom` | 6px | 4px |

Result: Color chips (both products) fit on one line. Roller sizes still 2+2+1.

**Commit `537681f`** — `ui: tighten chip padding 6→5px for 3-column roller sizes`
| Property | Before | After |
|----------|--------|-------|
| `variantChip.paddingHorizontal` | 6px | 5px |

Result: All three cases now display as intended (rollers 3+2, colors single-row).
